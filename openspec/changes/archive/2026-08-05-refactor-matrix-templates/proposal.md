## Why

The codebase carries an unused `design-matrix.html.mustache` template and seven Mustache partials that were created during the `externalize-html-templates` change but never wired into the rendering path. The `MatrixGenerator` also exposes three dead methods (`generateDesignMatrix`, `generateRequirementsMatrix`, `generateAllMatrices`) that nothing calls. Removing this dead code and refactoring the one live `matrix.html.mustache` template to use partials improves maintainability and reduces confusion about which template is authoritative.

## What Changes

- **Remove** `src/templates/design-matrix.html.mustache` — dead template, never rendered
- **Remove** `src/templates/partials/` directory (7 files) — partials for the dead design-matrix template, data contract incompatible with the live matrix template
- **Remove** three dead methods from `MatrixGenerator.ts`: `generateRequirementsMatrix()`, `generateDesignMatrix()`, `generateAllMatrices()`
- **Refactor** `src/templates/matrix.html.mustache` into a main template with four new partials (`styles`, `header`, `matrix-row`, `footer`) that match the actual data contract produced by `exportToHTML()`
- No change to `exportToHTML()` or `TemplateRenderer` — same data contract, same render call

## Capabilities

### New Capabilities

- `template-partials`: The matrix HTML template is split into reusable Mustache partials (`styles`, `header`, `matrix-row`, `footer`) for cleaner structure and maintainability

### Modified Capabilities

None — no user-facing behavior or output changes. This is pure internal cleanup and refactoring.

## Impact

- `src/templates/` — delete 8 files, create 4 new partials, modify 1 template
- `src/MatrixGenerator.ts` — remove 3 dead methods (~47 lines)
- `lib/templates/` — regenerated by `npm run build`
- Tests: 194 tests pass without changes (tests only assert structural HTML presence: `<html>`, `<table>`)
