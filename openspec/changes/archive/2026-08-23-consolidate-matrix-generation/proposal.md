## Why

Matrices are now generated by the extension at build time — registered as content-catalog attachments during `contentClassified` and written to the output directory at `sitePublished`. The example site's `run-example.js` still generates the same matrices separately into `modules/ROOT/attachments/traceability/`, where they are committed and then replaced by the extension's output at build time. That is redundant and drifts unless manually re-run.

## What Changes

- `run-example.js` stops generating matrices; it keeps processing files and exporting the Neo4j CSV (`nodes.csv`, `relationships.csv`), which the extension does not generate.
- The 12 committed matrix files are removed from `modules/ROOT/attachments/traceability/`; the extension registers them at build time.
- Docs, the update-example-site skill, and two specs that describe matrix generation via the CLI are updated to point at the extension.
