## Why

When a page containing `[item]` macros is moved to a different Antora module (e.g., `ROOT/pages/requirements.adoc` → `requirements/pages/index.adoc`), cross-references generated by `traceability:outgoing[]` and `traceability:incoming[]` break because the component and module names are stripped during source file normalization. Antora cannot resolve `xref:architecture#ARC-001` from the `requirements` module — it needs `xref:ROOT:architecture#ARC-001`.

## What Changes

- **Store component and module context on items**: Capture the Antora component and module names alongside the page path during `contentClassified` processing
- **Include component/module in xref generation**: `buildXref` emits the correct xref prefix for cross-module and cross-component references, matching Antora's `xref:component:module:page#id` resolution hierarchy
- **Update LinkResolver**: Generate matrix links with module-aware paths so HTML matrices can navigate to items in any module
- **Update source file normalization**: Keep `normalizeSourceFile` producing `page`, with component/module stored separately

## Capabilities

### New Capabilities
- `cross-module-xref`: Xrefs generated inside item block macros (`traceability:outgoing[]`, `traceability:incoming[]`) include the Antora component and module prefix when the target item resides in a different component or module, enabling correct cross-module and cross-component navigation

### Modified Capabilities
- `traceability-links-macro`: `buildXref` and `normalizeSourceFile` must become module-aware; cross-module xref scenarios added to spec
- `matrix-item-linking`: LinkResolver must handle module-prefixed source files when generating HTML matrix links

## Impact

- **types.ts**: Add `component?: string` and `module?: string` fields to `Item`
- **antora-extension.ts**: `processAsciiDocFile`, `expandOutgoingMacros`, `expandIncomingMacros`, `buildXref` — capture and use component/module from `file.src.component` / `file.src.module`
- **LinkResolver.ts**: `itemToHtmlPath` — preserve module prefix when present
- **DocumentParser.ts** / **CLI**: Optional `component` and `module` in parse options (undefined for CLI usage)
- **Tests**: New cross-module and cross-component xref scenarios; updated normalization assertions
- **Example site**: Already has the multi-module layout (ROOT + requirements); this fix makes it work
