= Architecture Decision Records

== What is an ADR?

An Architecture Decision Record (ADR) is a document that captures an important architectural decision made along with its context and consequences.

For more information about ADRs, see:

* https://adr.github.io/[ADR GitHub organization]
* https://github.com/joel-costigliola/architecture-decision-record[Architecture Decision Record repository]

== ADR Format

We use the https://github.com/architecture-decision-record/architecture-decision-record/tree/main/locales/en/templates/decision-record-template-by-gig-cymru-nhs-wales[GIG Cymru NHS Wales template] as the basis for our ADRs.

Each ADR has:

* A unique number (sequential)
* A title describing the decision
* Status (Accepted, Rejected, Deprecated, etc.)
* Context explaining the problem
* Decision describing the chosen solution
* Consequences (positive and negative)
* Implementation details
* Validation results

== How to Add a New ADR

1. Create a new file in this directory with the next sequential number
2. Use the template format (see existing ADRs for reference)
3. Fill in all sections with appropriate detail
4. Add the ADR to the table above
5. Submit a pull request for review

== ADR Status Definitions

| Status | Description |
|--------|-------------|
| ✅ Accepted | Decision has been agreed upon and implemented |
| ❌ Rejected | Decision was considered but not adopted |
| ⚠️ Proposed | Decision is under consideration |
| 🗑️ Deprecated | Decision has been superseded by a new decision |
| 🔄 Amended | Decision has been modified after implementation |
