= 1. Use pre-commit for Git Hooks

== Status

✅ Accepted

== Context

We need a reliable way to enforce code quality checks before commits are made to the repository.
Previously, the project used Husky + lint-staged for this purpose.

The requirements for our git hooks are:

* Run Biome linting and formatting on staged TypeScript files
* Run Biome formatting on staged Markdown, JSON, and YAML files
* Prevent commits with lint errors
* Support additional quality checks (large files, trailing whitespace, line endings, merge conflicts)
* Work across different operating systems
* Be maintainable and well-supported

== Decision

We will use https://github.com/pre-commit/pre-commit[pre-commit] as our git hooks manager instead of Husky + lint-staged.

== Detailed Decision

=== Why pre-commit?

1. **Language-agnostic**: pre-commit is written in Python and works with any language, making it suitable for multi-language projects
2. **Rich ecosystem**: Access to 2000+ pre-built hooks from the pre-commit community
3. **Better isolation**: Each hook runs in its own virtualenv, preventing dependency conflicts
4. **Automatic updates**: `pre-commit autoupdate` keeps hooks current with minimal effort
5. **Standard tool**: Widely adopted in the Python community and gaining traction in JavaScript/TypeScript projects
6. **More reliable**: Handles edge cases better than Husky, especially with file stashing
7. **Native git integration**: Designed specifically for git hooks with proper git awareness

=== Why not Husky?

While Husky is a good tool for Node.js projects, it has some limitations:

* Node.js-only (not suitable for multi-language projects)
* Less mature ecosystem for non-JavaScript hooks
* Requires additional tools (lint-staged) for file filtering
* More complex configuration
* Less reliable in edge cases

=== Alternatives Considered

| Option | Pros | Cons |
|--------|------|------|
| **pre-commit** | Language-agnostic, rich ecosystem, reliable, standard | Requires Python |
| Husky + lint-staged | Node.js native, familiar to JS devs | Node.js-only, less ecosystem |
| lefthook | Fast, multi-language | Less mature, smaller community |
| Git hooks (native) | No dependencies | Hard to maintain, no isolation |

== Consequences

=== Positive Consequences

* ✅ Single tool for all git hooks (not just pre-commit)
* ✅ Access to vast library of pre-built hooks
* ✅ Better isolation between hooks
* ✅ Automatic hook updates
* ✅ Works with any language in the repository
* ✅ More maintainable configuration

=== Negative Consequences

* ⚠️ Requires Python 3.7+ to be installed
* ⚠️ Slightly different configuration format (YAML vs JSON)
* ⚠️ Learning curve for developers unfamiliar with pre-commit

== Implementation

1. Install pre-commit:
   ```bash
   pip install pre-commit
   ```

2. Create `.pre-commit-config.yaml` with hooks:
   ```yaml
   repos:
     - repo: local
       hooks:
         - id: biome-check
           entry: npx biome check --apply
           files: \.(ts|tsx|js)$
         - id: biome-format
           entry: npx biome format --write
           files: \.(md|json|yaml|yml)$
     - repo: https://github.com/pre-commit/pre-commit-hooks
       rev: v4.5.0
       hooks:
         - id: check-added-large-files
         - id: trailing-whitespace
         - id: mixed-line-ending
         - id: check-merge-conflict
   ```

3. Install git hooks:
   ```bash
   pre-commit install
   ```

4. Remove Husky and lint-staged:
   ```bash
   npm uninstall husky lint-staged
   rm -rf .husky/
   ```

== Validation

The pre-commit setup has been tested and validated:

* ✅ All existing tests still pass (155 passing, 4 pre-existing failures)
* ✅ Pre-commit hooks run successfully on staged files
* ✅ Biome linting catches and fixes issues
* ✅ Biome formatting applies to staged files
* ✅ All additional hooks (large files, whitespace, etc.) work correctly
* ✅ Hooks can be manually run with `pre-commit run --all-files`
* ✅ Hooks can be updated with `pre-commit autoupdate`

== Notes

=== Python Requirement

pre-commit requires Python 3.7+ to be installed on the system.
This is a reasonable requirement as Python is commonly available on most development systems.

=== Migration from Husky

The migration from Husky to pre-commit was straightforward:

* Configuration: Moved from `package.json` + `.husky/` to `.pre-commit-config.yaml`
* Dependencies: Removed Husky and lint-staged, no new npm dependencies
* Functionality: All existing functionality preserved, with additional hooks added

=== Future Considerations

* Consider adding more hooks from the pre-commit ecosystem as needed
* Monitor pre-commit updates and run `pre-commit autoupdate` periodically
* Consider adding pre-push hooks for additional checks (e.g., test suite)
