= Use Cases
:traceability-links: true

This page captures the key user workflows for the Antora Tracer extension. Each use case traces into the requirements it motivates via `leads_to` relations — demonstrating how config extension adds domain-specific roles and relations beyond the built-in presets.

[#UC-001, item, role=use_case, title="Business Analyst writes traceable items in AsciiDoc"]
--
.Use Case: Author writes traceable items in AsciiDoc
[width=100%, cols="25h,75a"]
|===
| ID | UC-001
| Title | Business Analyst writes traceable items in AsciiDoc
| Goal | Business Analyst writes traceable items so that the project establishes complete end-to-end traceability across the software development lifecycle
| Primary Actor | Business Analyst
| Preconditions | The project uses Antora as its site generator And the Antora Tracer extension is installed in the playbook And a `traceability.yml` config is loaded with at least one role defined And the Business Analyst has write access to `.adoc` files in the pages or partials directories
| Trigger | Business Analyst opens an `.adoc` file in their editor to add or update a traceable item
| Basic Flow |
. Business Analyst identifies a concept that needs to be traceable — a requirement, a stakeholder concern, a decision, or a dependency
. Business Analyst assigns the concept to a role defined in the project's traceability domain model (requirement, design, test, use case, etc.)
. Business Analyst writes a description of the concept in AsciiDoc format
. Business Analyst links the concept to related items already in the traceability graph using inline relationship macros
. Business Analyst includes rendering placeholders to display relationship lists in the output
. Business Analyst commits the file And triggers an Antora build
. The extension registers the item in the traceability graph And its relationships appear in the traceability matrix
| Alternate Flows |
. *Business Analyst uses a role not in config:* Extension registers the item with a warning. Processing continues.
. *Business Analyst links to a target that does not exist:* Extension stores the relationship with a warning. The matrix shows a partial link.
. *Business Analyst writes an incomplete item block:* The item may not register correctly in the traceability graph.
. *Business Analyst includes rendering placeholders but no relationships exist:* The placeholder is replaced with an empty section in the rendered output.
| Postconditions | The traceability graph contains the new item And all inline relationships are registered And the rendered page shows "Leads-to" or "Addressed-by" sections if placeholders were included And the traceability matrix reflects updated coverage
| Priority | High
| Frequency | Per item — multiple times per documentation session
| Notes | ⚠ Actor "Business Analyst" does not yet have a persona definition. The `[item]` macro syntax is documented in the User Guide and owned by REQ-001 through REQ-004 — this use case does not specify the exact syntax.
|===

[#UC-002, item, role=use_case, title="Author defines custom domain model via config"]
--
As a project lead, I want to define custom roles, relations, and matrices in
a `traceability.yml` file that extends a built-in preset, so that the extension
validates and traces items using my project's domain language. The config
overrides and extends the preset — adding new roles, restricting relations,
or defining custom matrices for my specific needs.

`antora-tracer next-id --prefix REQ -i docs/` so that I get the next
sequential ID without manually scanning existing items. The command
auto-detects the padding convention from existing IDs.
