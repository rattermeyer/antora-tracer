== RequirementsTraceabilityExtension

`src/index.ts` — the orchestrator.
Owns the `TraceabilityGraph`, delegates processing to `DocumentParser`, generation to `MatrixGenerator`, and export to `Neo4jExporter`.

[source,typescript]
----
export class RequirementsTraceabilityExtension {
  readonly graph: TraceabilityGraph;
  configLoader?: ConfigLoader;
  currentFile: string | null;
}

// Factory methods
RequirementsTraceabilityExtension.createWithConfig(configPath?: string): Promise<RequirementsTraceabilityExtension>;
RequirementsTraceabilityExtension.createWithPreset(presetName: string): RequirementsTraceabilityExtension;
----

|===

== TraceabilityGraph

`src/TraceabilityGraph.ts` — in-memory directed graph.
Items use component, version, and ID as their canonical storage key; unscoped items keep bare-ID keys.
Relationships are indexed and deduplicated by canonical source and target identities.
[source,typescript]
----
export class TraceabilityGraph {
  // Node management
  addItem(item: Item): void;
  getItem(id: string, component?: string, version?: string): Item | undefined;
  getAllItems(): Item[];
  getItemsByRole(role: string): Item[];
  getAllRoles(): string[];

  // Relationship management
  addRelationship(relationship: ItemRelationship): void;
  getRelationship(id: string): ItemRelationship | undefined;
  getAllRelationships(): ItemRelationship[];
  getRelationships(fromId: string, type?: string, component?: string, version?: string): ItemRelationship[];
  getReverseRelationships(targetId: string, type?: string, component?: string, version?: string): ItemRelationship[];

  // Query
  getRelatedItems(itemId: string, relationType?: string, component?: string, version?: string): Item[];
  getItemsWithRelationTo(itemId: string, relationType?: string, component?: string, version?: string): Item[];
  getRelationshipsByRoles(sourceRole: string, targetRole: string): ItemRelationship[];
  getRoleStatistics(): Record<string, number>;

  // Graph algorithms
  findPath(fromId: string, toId: string, maxDepth?: number, component?: string, version?: string): string[] | null;
  getImpactAnalysis(itemId: string, component?: string, version?: string): string[];

  // Validation
  validate(): ValidationResult;
  findCircularReferences(): string[];

  // Visualization
  toDot(fromId: string, depth?: number, component?: string, version?: string): string;
  toVegaLite(itemId?: string): string;

  // ID generation
  getNextId(prefix: string): string;

  // Lifecycle
  clear(): void;
  merge(other: TraceabilityGraph): void;
  setConfigLoader(configLoader: ConfigLoader): void;
}

interface ValidationResult {
  errors: string[];
  warnings: string[];
}
----

`addRelationship` validates: source exists, target exists, relation is allowed (if ConfigLoader is set).
Invalid relations are stored with a warning. `validate()` runs `findCircularReferences()`, a DFS-based cycle detector.

== DocumentParser

`src/DocumentParser.ts` — regex-based AsciiDoc parser.

[source,typescript]
----
export interface ParserResult {
  items: Item[];
  relationships: ItemRelationship[];
  warnings: ParserWarning[];
  errors: ParserError[];
}
----

Two-pass approach: find `[item]` block macros, then scan content for inline relationship macros (`<type>:<TARGET-ID>[]`).
Supports verbatim block exclusion, source file and line tracking.

== ItemBlockBounds

`src/ItemBlockBounds.ts` — the single authoritative locator for an item block's position and extent.

[source,typescript]
----
export interface ItemBlockBounds {
  itemId: string;          // Item ID as authored in the header
  headerStart: number;     // Absolute offset of the header's '['
  headerEnd: number;       // Absolute offset just past the header's ']'
  bodyStart: number;       // Absolute offset of the first body character
  bodyEnd: number;         // Absolute offset of the newline before the closing delimiter
  bodyTextStart: number;   // Absolute offset of the body's first non-whitespace character
  blockEnd: number;        // Absolute offset just past the closing delimiter
  delimiter: "--" | "===="; // The delimiter form
  startLine: number;       // 1-based line of the header
  endLine: number;         // 1-based line of the closing delimiter
  blockText: string;       // Header through closing delimiter
  bodyText: string;        // The item body, trimmed as `Item.content` is
}

export function itemBlockBoundsAtOffset(content: string, headerOffset: number): ItemBlockBounds | null;
export function itemBlockBoundsAtLine(content: string, sourceLine: number): ItemBlockBounds | null;
export function findItemBlocks(content: string): ItemBlockBounds[];
export function findVerbatimRanges(content: string): Array<{ start: number; end: number }>;
----

`itemBlockBoundsAtOffset` takes the absolute offset of the header's `[`; `itemBlockBoundsAtLine` takes a 1-based source line and resolves the offset itself.
Both return `null` when the position is not an item block — no delimiter, an unterminated block, or a header inside a `----`/`....` verbatim fence.
Offsets are the primitive; `startLine` and `endLine` are derived, and `content.slice(headerStart, blockEnd)` equals `blockText` exactly.
The parser, the CLI's `archive`/`remove`, and the Antora extension all locate blocks through this module, so the item-block grammar has one home.

== Neo4jExporter

`src/Neo4jExporter.ts` — exports the graph to Neo4j-compatible formats.

CSV node rows include `id` (authored ID), `identity` (canonical graph key), `component`, and `version`.
For playbook graphs, `identity` combines component, version, and ID with NUL separators.
For unscoped local graphs, it equals `id`.
CSV relationship rows use canonical node keys in `source` and `target`.
They retain authored endpoint IDs in `sourceId` and `targetId`.
Cypher creates and matches nodes by `identity`.

[source,typescript]
----
export class Neo4jExporter {
  constructor(graph: TraceabilityGraph);

  export(options: Neo4jExportOptions): Neo4jExportResult;
}

export interface Neo4jExportOptions {
  outputDir: string;
  format: 'csv' | 'cypher';
  includeContent?: boolean;
  includeAllAttributes?: boolean;
}

export interface Neo4jExportResult {
  nodesFile?: string;
  relationshipsFile?: string;
  cypherFile?: string;
  nodeCount: number;
  relationshipCount: number;
}
----

== GraphDiff

`src/GraphDiff.ts` — derives a delta between two graph snapshots by stable item ID.
Config-agnostic: no role names are hardcoded.

[source,typescript]
----
export interface ItemDelta {
  id: string;
  kind: "added" | "removed" | "modified";
  role: string;
  old?: Item;
  new?: Item;
  changedFields: string[];
}

export interface RelationshipDelta {
  kind: "added" | "removed";
  rel: ItemRelationship;
}

export interface GraphDiff {
  items: ItemDelta[];
  relationships: RelationshipDelta[];
}

export function diffGraphs(prev: TraceabilityGraph, next: TraceabilityGraph): GraphDiff;

export function diffSnapshots(prev: GraphSnapshot, next: GraphSnapshot): GraphDiff;
----

Items are matched by component-qualified identity (`component`, then `version` when present, then `id`); items without a component fall back to bare ID.
Items present only in `next` are `added`, only in `prev` are `removed`, and survivors are compared field-by-field (`title`, `content`, `role`, `status`, `attributes`) for `modified`.
Relationship changes are reported only for surviving items, except `supersedes` history links.

== GraphSnapshot

`src/GraphSnapshot.ts` — the canonical JSON snapshot format shared by `site-graph`, `diff-graphs`, and the extension's per-version `graph.json`.

[source,typescript]
----
export interface GraphSnapshot {
  format: number;                    // schema version, currently 1
  items: Item[];
  relationships: ItemRelationship[];
}

export const SNAPSHOT_FORMAT = 1;

export function serializeSnapshot(graph: TraceabilityGraph): string;
export function deserializeSnapshot(json: string): GraphSnapshot;
----

`serializeSnapshot` keeps item scope fields (`component`, `module`, `version`) and drops the per-page `pubUrl` and the build-machine `sourceRoot`.
`deserializeSnapshot` rejects unknown `format` values and malformed snapshots.

== Data Model

`src/types.ts`:

[source,typescript]
----
export interface Item {
  id: string;                        // Unique identifier
  title: string;                     // Display title
  content?: string;                  // Raw AsciiDoc content
  role: string;                      // User-defined role
  status?: string;                   // Free-form status
  tags?: string[];                   // Comma-separated header tags, parsed as a list
  attributes: Record<string, string>; // Additional attributes
  sourceFile?: string;               // Repository source reference (see below)
  sourceLine?: number;               // Line number in source
  component?: string;                // Antora component name (absent for CLI)
  module?: string;                   // Antora module name (absent for CLI)
  version?: string;                  // Antora component version (absent for CLI)
  pubUrl?: string;                   // Antora published URL (absent for CLI)
  sourceRoot?: string;               // Content-source root the sourceFile is relative to (absent for CLI)
}

export interface ItemRelationship {
  id: string;
  fromId: string;                    // Authored source item ID
  targetId: string;                  // Authored target item ID
  type: string;                      // User-defined relation type
  component?: string;                 // Source Antora component
  version?: string;                  // Source Antora version
  fromIdentity?: string;              // Canonical source identity after resolution
  targetIdentity?: string;            // Canonical target identity after resolution
  sourceFile?: string;
  line?: number;                     // File line of the declaring macro or header attribute
  autoGenerated?: boolean;
  inverseOf?: string;
}
----

`sourceFile` is the item's repository source reference, not a filesystem location.
Page items use the source path given by the caller (the content catalog for Antora, the input path for the CLI), with the `.adoc` extension and anything up to and including the last `pages/` segment stripped.
For items in partial files it is the partial's `http(s)` view URL when the content source provides one, and the repository-relative source path otherwise.
A local content source produces a `file://` view URL, which points at the build machine's worktree, so those partial items fall back to the repository-relative path.
No `sourceFile` value therefore exposes a build-machine directory, including when it is serialized into a `graph.json` snapshot or a Neo4j export.

`sourceRoot` is the absolute directory of the content source an item was harvested from, so that its relative `sourceFile` resolves to exactly one file even when two sources declare the same relative path.
It is set only when an item comes from a playbook source whose origin provides a worktree: a harvest records the repository worktree joined with the source's start path, and a source read from the git tree (a bare repository) records no root.
Items built from local files without a playbook carry no root, and a consumer treats that as the single-source case where its own input directory is the root.
Because the root is a build-machine path, `serializeSnapshot` and the extension's `graph.json` writer drop it alongside `pubUrl`, so no published artifact exposes it.

== SiteGraph

`src/SiteGraph.ts` — harvest a playbook's complete cross-source graph without generating site output.

[source,typescript]
----
export interface HarvestedFile {
  path: string;                      // Component-root-relative source path
  content: string;
  component?: string;
  module?: string;
  version?: string;
  pubUrl?: string;
  sourceRoot?: string;               // Content-source root (absent without a worktree)
}

export async function harvestSiteFiles(playbookPath: string): Promise<HarvestedFile[]>;
----

Each harvested file records its content-source root, derived from the file's Antora origin metadata, so a consumer can resolve `path` to exactly one file on disk.

`src/SourcePath.ts` — resolve an item's relative `sourceFile` to an absolute path:

[source,typescript]
----
export function resolveSourceFilePath(
  input: string,
  sourceFile: string | undefined,
  sourceRoot?: string,
): string;
----

The recorded `sourceRoot` is preferred; when it is absent the caller's `input` directory is used.
A resolved path that escapes the chosen root is rejected rather than returned.
