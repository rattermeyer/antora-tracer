= Traceability Matrices
:description: Explanation of traceability matrices and how to use them

This page explains the traceability matrices generated by the Requirements Traceability Extension and how to interpret them.

== What is a Traceability Matrix?

A traceability matrix is a table that shows the relationships between different types of traceability elements (requirements, implementations, tests, documents). It provides a visual representation of which requirements have implementations, which have tests, and the overall coverage of your traceability.

== Matrix Types

The extension generates three types of matrices:

=== Requirements-to-Implementation Matrix (req-impl)

Shows which requirements have implementations.

**Purpose:** Track implementation progress

**Columns:**

| Column | Description |
|--------|-------------|
| Requirement ID | Unique identifier of the requirement |
| Title | Human-readable title of the requirement |
| Implementations | List of implementations that implement this requirement |
| Tests | List of tests that test this requirement |
| Status | Coverage status (✓ Complete, ⚠ Partial, ✗ Missing) |

**Use Case:** Project managers and developers can quickly see which requirements have been implemented and which are still pending.

=== Requirements-to-Test Matrix (req-test)

Shows which requirements have tests.

**Purpose:** Track test coverage

**Columns:** Same as req-impl matrix

**Use Case:** QA engineers and developers can verify that all requirements have appropriate test coverage.

=== Full Traceability Matrix (full)

Shows all relationships between all types of elements.

**Purpose:** Complete view of all traceability

**Columns:** Varies based on content, but typically includes all element types and their relationships

**Use Case:** Comprehensive view for audits, reviews, or complex analysis.

== Status Indicators

Each requirement in the matrix has a status indicator:

| Status | Icon | Meaning |
|--------|------|---------|
| Complete | ✓ | Requirement has both implementation and tests |
| Partial | ⚠ | Requirement has implementation OR tests but not both |
| Missing | ✗ | Requirement has neither implementation nor tests |

== Coverage Metrics

At the bottom of each matrix, you'll find coverage metrics:

* **Total Requirements**: Total number of requirements defined
* **Requirements with Implementation**: Number of requirements with at least one implementation
* **Requirements with Tests**: Number of requirements with at least one test
* **Implementation Coverage**: Percentage of requirements with implementations
* **Test Coverage**: Percentage of requirements with tests

== Example Matrix

Here's what a typical matrix looks like:

| Requirement | Title | Implementations | Tests | Status |
|-------------|-------|----------------|-------|--------|
| REQ-001 | User Authentication | IMP-001 | TEST-001 | ✓ Complete |
| REQ-002 | Data Encryption | IMP-002 | | ⚠ Partial |
| REQ-003 | Audit Logging | | | ✗ Missing |

**Summary:**

* Total Requirements: 3
* Requirements with Implementation: 2 (66.7%)
* Requirements with Tests: 1 (33.3%)
* Implementation Coverage: 66.7%
* Test Coverage: 33.3%

== Matrix Formats

The extension generates matrices in multiple formats:

=== CSV Format

Comma-separated values that can be opened in spreadsheet applications.

**Features:**

* Easy to import into Excel, Google Sheets, etc.
* Can be used for further analysis
* Simple, universal format

**Example:**
```csv
Requirement ID,Requirement Title,Implementations,Tests,Status
REQ-001,User Authentication,IMP-001,TEST-001,✓ Complete
REQ-002,Data Encryption,IMP-002,,⚠ Partial
```

=== HTML Format

Styled, interactive HTML tables with color-coded status indicators.

**Features:**

* Color-coded status badges (green for complete, orange for partial, red for missing)
* Responsive design that works on mobile devices
* Professional styling matching Antora UI
* Easy to navigate and read

**Example:**
```html
<table>
  <tr>
    <td>REQ-001</td>
    <td>User Authentication</td>
    <td>IMP-001</td>
    <td>TEST-001</td>
    <td><span class="status-complete">✓ Complete</span></td>
  </tr>
</table>
```

== How to Use Matrices

=== For Project Managers

* Use the req-impl matrix to track implementation progress
* Use the coverage report to identify gaps in traceability
* Use the full matrix for comprehensive audits

=== For Developers

* Use the matrices to see which requirements need implementation
* Use the matrices to see which requirements need tests
* Use the relationships to understand dependencies

=== For QA Engineers

* Use the req-test matrix to verify test coverage
* Use the matrices to trace requirements to tests
* Use the coverage report to identify untested requirements

=== For Auditors

* Use the full matrix to verify all traceability links
* Use the matrices to trace from requirements to implementations to tests
* Use the coverage report to verify completeness

== Best Practices

1. **Start with a few key requirements** - Don't try to trace everything at once
2. **Use consistent ID formats** - Stick to TYPE-NUMBER format (e.g., REQ-001)
3. **Create explicit relationships** - Use inline macros to link elements
4. **Review matrices regularly** - Use them to track progress and identify gaps
5. **Keep requirements up to date** - Update requirements as the project evolves
