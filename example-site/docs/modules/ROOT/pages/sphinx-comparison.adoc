= Sphinx Needs vs Requirements Traceability Extension
:description: Side-by-side comparison for users migrating from Sphinx Needs

This page provides a comparison between https://sphinx-needs.readthedocs.io/[Sphinx Needs] and the Requirements Traceability Extension for Antora/AsciiDoc. It's designed to help users migrating from Sphinx to Antora understand the differences and similarities.

== Overview

[cols="1,2,2"]
|===
| Aspect | Sphinx Needs | Requirements Traceability Extension

| *Platform*
| Sphinx (Python)
| Antora (JavaScript/Node.js)

| *Documentation Format*
| reStructuredText
| AsciiDoc

| *Integration*
| Sphinx extension
| Antora extension

| *Language*
| Python
| TypeScript

| *Maturity*
| Mature (several years)
| New (2026)

| *Community*
| Large, active
| Growing
|===

== Requirement Definition

[cols="1,2,2"]
|===
| Feature | Sphinx Needs | Requirements Traceability Extension

| Syntax
| `:need:` directive
| `[req]` block macro

| ID Format
| Free-form (recommends NEED-XXX)
| TYPE-NUMBER (e.g., REQ-001)

| Title
| Optional
| Optional

| Description
| Multi-line content
| Multi-line content

| Status
| Customizable
| Customizable (draft, approved, etc.)

| Example
a| `:need:` User Login +
All users must be able to log in.
a| `[req, id=EXAMPLE-101]` +
`\====` +
All users must be able to log in. +
`\====`
|===

== Implementation Definition

|===

== Syntax Comparison

=== Sphinx Needs

[source,rst]
----
.. need:: User Login
   :id: USER-LOGIN
   :status: open
   :tags: security, frontend

   All users must be able to log in to the system.

.. need:: Password Reset
   :id: PASS-RESET
   :status: open
   :tags: security

   Users must be able to reset their password.

.. req:: Login Service
   :id: LOGIN-SVC
   :status: implemented

   :satisfies: USER-LOGIN

   The service that handles user authentication.
----

=== Requirements Traceability Extension

[source,asciidoc]
----
[req, id=DEMO-001, title="User Login", status=approved]
====
All users must be able to log in to the system.
====

[req, id=DEMO-002, title="Password Reset", status=approved]
====
Users must be able to reset their password.
====

[imp, id=DEMO-IMP-001, title="Login Service", status=done]
====
The service that handles user authentication.
====

implements:DEMO-001[]
----

== Key Differences

=== Philosophy

*Sphinx Needs:*

* Designed for Sphinx documentation
* Uses reStructuredText syntax
* Highly customizable (can define custom need types, statuses, etc.)
* Mature ecosystem with many plugins

*Requirements Traceability Extension:*

* Designed for Antora documentation
* Uses AsciiDoc syntax
* Opinionated with sensible defaults
* Focused on simplicity and ease of use
* Built-in matrix generation with modern styling

=== Strengths

*Sphinx Needs Strengths:*

* Mature and battle-tested
* Large community and ecosystem
* Highly customizable
* Good for complex requirements management
* Integrates well with Sphinx ecosystem

*Requirements Traceability Extension Strengths:*

* Native Antora integration
* Modern AsciiDoc syntax
* Built-in HTML matrix generation with styling
* Simple setup and configuration
* Fast and performant (TypeScript, ESM)
* Good for documentation-focused use cases

== Migration Guide

If you're migrating from Sphinx Needs to the Requirements Traceability Extension:

=== Step 1: Convert Syntax

[cols="1,1"]
|===
| Sphinx Needs | Requirements Traceability Extension

| `:need:`
| `[req]`

| `:req:`
| `[imp]`

| `:test:`
| `[test]`

| `:doc:`
| `[doc]`

| `:satisfies:`
| `satisfies:`

| `:implements:`
| `implements:`

| `:tests:`
| `tests:`

| `:verifies:`
| `verifies:`

| `:doc:`
| `documents:`

| `:depends:`
| `depends:`
|===

=== Step 2: Update IDs

Sphinx Needs uses free-form IDs (e.g., USER-LOGIN, NEED-001).
The Requirements Traceability Extension recommends TYPE-NUMBER format (e.g., REQ-001, IMP-001).

You can:

* Keep your existing IDs (they'll work, but generate warnings)
* Update to the recommended format
* Use a prefix that matches your project

=== Step 3: Update Configuration

Sphinx Needs configuration goes in `conf.py`:

[source,python]
----
# conf.py
extensions = ['sphinx_needs']
needs_types = [
    dict(name="req", title="Requirement", prefix="REQ_", color="#BFD8D2"),
    dict(name="imp", title="Implementation", prefix="IMP_", color="#D8BFD2"),
]
----

Requirements Traceability Extension configuration goes in `antora.yml`:

[source,yaml]
----
# antora.yml
extensions:
  - require: antora-requirements-traceability
----

Much simpler!

=== Step 4: Run and Verify

After migrating your content:

[source,bash]
----
# For Sphinx Needs
make html

# For Requirements Traceability Extension
npx antora antora.yml
----

Verify that:

* All requirements are parsed correctly
* All relationships are established correctly
* Matrices are generated correctly
* Coverage report shows expected metrics
